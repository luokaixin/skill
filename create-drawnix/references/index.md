# 按「图形骨架」选型

拿到需求时，先判断**骨架**，不要先判断名字。骨架决定用哪些图元；名字只是叫法，
同一个名字在不同人嘴里可能指完全不同的结构。

## 一、十四种骨架

| 骨架 | 判据 | 主要图元 | 关键约束 |
| --- | --- | --- | --- |
| **时间轴** | 有先后顺序，横排或竖排一串节点 | 虚线轴 + 圆点 + 卡片 | 卡片与圆点间距一致；上下交替时轴线居中 |
| **闭环** | 有「循环 / 回路 / 自驱动」语义 | 环 = 填充多边形；箭头 = 轮廓多边形 | 环必须完整，环内禁白色形状 |
| **比例环** | 有百分比，表达份额 | 多段弧（填充面）+ 中心留白 | 各段首尾留缝；弧用填充不用描边 |
| **放射** | 一个中心 + 多个辐射维度 | 六边形 / 弧轴 / 三角扇 | 中心与外围等距；六边形要平顶 |
| **矩阵** | 两个维度交叉分格 | `table-node` 等高网格 | 所有格子行数一致 |
| **表格** | 纯行列数据 | `table-node` | `size` = 列宽和 × 行高和 |
| **泳道** | 有「谁来做」或「哪个阶段」 | 分层底框 + 卡片 | 泳道头固定在轴端；卡片不出泳道 |
| **层级树** | 上下级、汇报关系 | 卡片 + T 形分支线 + 锚点 | 同层卡片等高；分支线水平段对齐 |
| **流程** | 有判定、多路径 | `shape-diamond` / `shape-flow` + 箭头 | 判定框出口对齐；箭头不交叉 |
| **时序** | 有消息往返、生命线 | 参与者框 + 激活条 + 绑定连线 | 端点落在激活条外缘，不是生命线中心 |
| **鱼骨** | 因果归因 | 主脊 + 斜骨 + 浮标签 | 标签浮在线段中点，不与任何节点连线 |
| **便签墙** | 自由贴、无严格结构 | `sticky-node` + 分区 | 便签等大；分区包住便签 |
| **分组列** | 多组并列展开 + 底部汇总 | 直角框 + 骑跨胶囊 + 汇流线 | 胶囊必须 `shape-full-rounded-rect` |
| **模型卡** | 某个方法论的结构化清单 | 卡片 + 表 + 圆 + 箭头混合 | 按方法论自身的层级组织 |

## 二、三种范式（最易混）

| | A 类：展示型 | B 类：主题树 | C 类：可录入 |
| --- | --- | --- | --- |
| 目的 | 示意，用户改文案 | 画布里继续增删节点 | 用户直接填表 |
| 文字 | 全部 `text-node` | `topic.attrs.label` | `table-node` 单元格 |
| 结构 | 手算坐标 | `topic` + 树边（无 `lineType`） | 网格 |
| 典型 | 时间线、闭环、金字塔 | 思维导图、主题树时间线 | 矩阵、分组列表 |

**最容易犯的错**：把「时间线示意图」做成 B 类（`topic` + 时间线布局），
得到的是可展开的链条主题树，和一张固定的时间线图完全不是一个东西。

判断方法：问「用户要在这张图上继续增删节点吗？」要 → B 类；只改文字 → A 类。

## 三、闭环 vs 比例环（最容易混的一对）

| | 闭环（飞轮类） | 比例环（环形图） |
| --- | --- | --- |
| 环 | **完整一圈**，收成 1 个箭头 | **多段开口弧**，每段各 1 个箭头 |
| 语义 | 单向流动、自我强化 | 若干部分占比之和为 100% |
| 是否有数字 | 无 | 每段标百分比，中心可标总量 |
| 方法 | `ring_arrow()` | `arc_arrow()` 分段 |

用错的表现：闭环用分段弧 → 环是断的；比例环用单箭头 → 只有一个箭头，其它段没有指向。

## 四、放射族三兄弟

| | 蜂巢 | 雷达图 | 金字塔 |
| --- | --- | --- | --- |
| 排布 | N 个六边形边对边咬合 | N 条轴从中心放射，连成多边形 | 横向分层的梯形堆叠 |
| 语义 | 维度并列、无优先级 | 多维评分对比 | 层级递进、自下而上 |
| 关键约束 | 六边形必须平顶；间距先扩 `g/2` | 各轴等角；网格同心 | 各层等高或等比；文字居中对齐 |
| 陷阱 | 用默认朝向拼不上 | 轴标签溢出 | 层高不均导致文字错位 |

## 五、各骨架的实现要点

### 5.1 时间轴

单事件 = 底框 + 内缩色条 + 日期/标题/说明三个文本节点 + 圆点 + 竖线。

- 色条**四边内缩**，宽度通栏内缩，不要顶满也不要缩成只包住日期
- 说明文字的高度按行数给：单行 22、两行 44、三行 62
- 上下交替时，轴上与轴下的卡片分别按圆点半径 + 间距推算 y

### 5.2 闭环

- 环：完整 360° **实心环形面**（外弧正向 + 内弧反向 + `Z`）
- 箭头：斜跨环带的**单个实心多边形**，轮廓自带内凹
- 环外装饰件：与环体完全脱开，最近角距离 > 环外径

自检：环带逐度无空洞 + 连通块数 = 1（主体）+ N（装饰件）。

### 5.3 比例环

- 每段是一条弧形填充面，段间留 1–2° 白缝
- 百分比标签放在**该段中角、环带中线**位置
- 中心留白直径建议为 `外径 − 环宽 − 20`，放总量或核心结论

### 5.4 放射 / 蜂巢

- 六边形用 6 顶点 `pen-stroke` 自画（平顶）
- 间距：`DX = 0.75 × (W + 2g/√3)`、`DY = H + g`
- 中心坐标：`(0, ±DY)` 与 `(±DX, ±DY/2)`
- 格内多段文字（标题 / 分隔线 / 释义）用独立 `text-node` 叠加，不要塞进 `attrs.label`
- 分隔线长度取该高度处内宽的 60%，避免顶到斜边

### 5.5 矩阵

- 所有格子行数统一，不足补空行
- `Q_H = 表头高 + 行高 × 行数`，由行数反算而非预设
- 轴标签坐标由**实际表格边界**反推，不要用 `Q_H` 手算

### 5.6 泳道

两种实现：

| 方式 | 适合 | 说明 |
| --- | --- | --- |
| `table-node` | 规则网格、每格内容等长 | 表头行做泳道名，`rowDragged` 固定 |
| 分层底框 + 卡片 | 卡片大小不一 | 每层一个通栏矩形做底，卡片自由摆放 |

### 5.7 层级树

- 同层卡片统一高度，否则水平分支线会错开
- 分支线用真实节点当端点；T 形横干横跨多列时，端点不在任何节点上，
  需要 1×1 锚点（这是锚点的合法用途之一）
- 锚点总数仍要控制在 10 个内

### 5.8 流程

- 判定框出口对齐：是/否分支分别从左右或上下引出
- 箭头统一 `endCap: 3`
- 回环线容易与其它线交叉，优先调整节点位置而不是加折点

### 5.9 时序

见 [builder-workflow.md](builder-workflow.md) §5.5。核心三条：

1. 不用自带生命线的图元
2. 消息端点落在激活条外缘
3. 激活条按消息区间合并

### 5.10 鱼骨

- 主脊为一条水平粗线，斜骨从主脊斜向引出
- 斜骨上的标签用 `text-node` **浮在线段中点**，不与任何节点连线
  （一旦连线，会参与布局、被拖乱）
- 末梢小横线与斜骨垂直

### 5.11 便签墙

- 便签统一尺寸，间距一致
- 分区用 `section`，`data.title` 与 `attrs.label.text` 都写
- 便签默认文字 20px，注意与字号白名单一致

### 5.12 分组列

- 外层容器直角（`rx: 0`），白底黑边
- 标题胶囊**骑跨**在容器顶边：`y = 容器顶 − 胶囊高/2`
- 胶囊必须 `shape-full-rounded-rect`
- 各组列宽与间距一致；底部汇总框宽度 = 各组总宽

## 六、选型自检

动手前回答三个问题：

1. **用户要在这张图上继续增删节点吗？** 要 → B 类主题树；不要 → A 类展示型
2. **是「流动」还是「占比」？** 流动 → 闭环；占比 → 比例环
3. **有没有两个轴？** 有 → 矩阵 / 四象限；没有 → 列表或放射

三个问题答完，骨架基本就定了。剩下的是套用该骨架的约束。
