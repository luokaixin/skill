# Dify 应用类型选择决策指南

本文档帮助根据业务需求选择最合适的 Dify 应用类型。

## 决策树

```
用户需求
  │
  ├─ 需要多轮对话？
  │   ├─ 是
  │   │   ├─ 需要模型自主决策和调用工具？
  │   │   │   ├─ 是 → Agent（智能体）
  │   │   │   └─ 否
  │   │   │       ├─ 每条消息需要触发复杂流程？
  │   │   │       │   ├─ 是 → Chatflow（对话流）
  │   │   │       │   └─ 否 → Chatbot（聊天助手）
  │   │   └─ 否
  │       └─ 需要多步骤处理？
  │           ├─ 是 → Workflow（工作流）
  │           └─ 否 → Text Generator（文本生成）
  │
  └─ 确定类型后，检查以下增强需求：
      ├─ 需要知识库？ → 添加 Knowledge Retrieval 节点
      ├─ 需要外部 API？ → 添加 HTTP Request 节点
      ├─ 需要条件分支？ → 添加 IF/ELSE 节点
      ├─ 需要批量处理？ → 添加 Iteration 节点
      ├─ 需要定时触发？ → 使用 Trigger（Workflow）
      └─ 需要状态记忆？ → 使用会话变量（Chatflow）
```

## 五种应用类型对比

| 维度 | Chatbot | Agent | Text Generator | Workflow | Chatflow |
|------|---------|-------|---------------|----------|----------|
| **交互模式** | 多轮对话 | 多轮对话 | 单次输入输出 | 一次执行 | 多轮对话 |
| **流程编排** | 无 | 无 | 无 | DAG 可视化 | DAG 可视化 |
| **模型自主性** | 低 | 高 | 低 | 低 | 低 |
| **工具调用** | 不支持 | 支持 | 不支持 | 节点配置 | 节点配置 |
| **知识库** | 支持 | 支持 | 支持 | 支持 | 支持 |
| **条件分支** | 不支持 | 不支持 | 不支持 | 支持 | 支持 |
| **循环/迭代** | 不支持 | 不支持 | 不支持 | 支持 | 支持 |
| **对话记忆** | 内置 | 内置 | 无 | 无 | 内置 |
| **终点节点** | - | - | - | Output | Answer |
| **DSL mode** | chat | agent | - | workflow | advanced-chat |
| **适合场景** | 简单问答 | 自主任务 | 翻译/摘要 | 自动化流水线 | 交互式助手 |

## 场景匹配指南

### 适合 Chatbot 的场景

- **简单知识库问答**：用户提问 → 知识库检索 → 模型回答
- **通用对话助手**：基于提示词的对话，无需复杂流程
- **特点**：快速搭建，配置简单，无需流程编排

**典型配置**：模型 + 提示词 + 可选知识库

### 适合 Agent 的场景

- **数据分析助手**：需要调用搜索、数据库查询等工具
- **自主任务执行**：模型决定使用哪些工具、何时使用
- **多步骤推理**：需要模型自主规划执行路径
- **特点**：模型自主决策，灵活性最高，但可控性较低

**典型配置**：模型 + 提示词 + 工具集 + 最大迭代次数

**模型要求**：推荐推理能力强且原生支持 Function Calling 的模型（如 GPT-4o、Claude 3.5）

### 适合 Text Generator 的场景

- **文本翻译**：输入文本 → 输出翻译
- **内容摘要**：输入长文 → 输出摘要
- **SQL 生成**：输入需求 → 输出 SQL
- **格式转换**：输入非结构化文本 → 输出结构化数据
- **特点**：单轮交互，无对话历史，适合明确的输入输出任务

**典型配置**：模型 + 提示词 + 输入变量定义

### 适合 Workflow 的场景

- **自动化报告生成**：定时触发 → 数据采集 → 分析 → 生成报告
- **批量内容生成**：输入主题列表 → 逐个生成内容 → 汇总输出
- **数据处理流水线**：多步骤数据处理，含条件分支
- **RAG 问答（复杂版）**：检索 → 判断是否有结果 → 分支处理
- **特点**：一次执行到底，适合无需交互的自动化任务

**典型配置**：Start → [多个处理节点] → Output

**触发方式**：
- 手动运行
- 定时触发（Trigger Schedule）
- Webhook 触发
- 集成事件触发

### 适合 Chatflow 的场景

- **智能客服**：每条消息触发流程，含意图识别、知识库检索
- **引导式问答**：根据用户输入动态选择处理路径
- **多步骤对话助手**：需要在对话中执行复杂流程
- **带审核的对话**：在回复前进行内容审核或后处理
- **特点**：结合了对话能力与流程编排，Chatflow = 对话层 + Workflow

**典型配置**：Start → [处理节点] → Answer

## 增强功能决策

在确定基础应用类型后，按需添加以下增强：

### 知识库（RAG）
**判断标准**：需要基于私有文档/知识库回答问题
**添加方式**：
- Chatbot/Agent：直接配置知识库
- Workflow/Chatflow：添加 Knowledge Retrieval 节点
- 需要：Embedding 模型 + 知识库数据

### 外部 API 集成
**判断标准**：需要调用外部服务（如发送通知、查询数据）
**添加方式**：Workflow/Chatflow 中添加 HTTP Request 节点

### 条件分支
**判断标准**：不同输入需要不同处理路径
**添加方式**：添加 IF/ELSE 节点

### 批量处理
**判断标准**：需要对列表中的每个元素执行相同操作
**添加方式**：添加 Iteration 节点

### 状态记忆
**判断标准**：需要跨对话轮次记住用户信息或偏好
**添加方式**：Chatflow 中使用会话变量（Conversation Variables）

### 定时执行
**判断标准**：需要定期自动运行（如每日报告）
**添加方式**：Workflow 中配置 Trigger Schedule

## 常见组合模式

### 模式 1：知识库问答（简单版）
```
类型：Chatbot
配置：模型 + 提示词 + 知识库
```

### 模式 2：知识库问答（增强版）
```
类型：Chatflow
流程：Start → Knowledge Retrieval → IF/ELSE（有结果?）→ LLM（生成回答）/ LLM（兜底回答）→ Answer
```

### 模式 3：意图路由客服
```
类型：Chatflow
流程：Start → Question Classifier → [分类1: LLM+知识库] / [分类2: LLM+工具] / [分类3: LLM兜底] → Answer
```

### 模式 4：多步内容生成
```
类型：Workflow
流程：Start → Parameter Extractor → IF/ELSE（验证）→ LLM（分析）→ Iteration（批量生成）→ Output
```

### 模式 5：数据分析 Agent
```
类型：Agent
配置：模型 + 工具集（搜索、代码执行、数据库查询）+ 最大迭代 5-10 次
```

### 模式 6：自动化报告
```
类型：Workflow
触发：Schedule（每日 9:00）
流程：Trigger → HTTP Request（获取数据）→ Code（处理数据）→ LLM（分析）→ LLM（生成报告）→ Output
```

### 模式 7：多模态文档处理
```
类型：Workflow
流程：Start（文件上传）→ Doc Extractor → LLM（分析）→ Code（结构化）→ Output
```
